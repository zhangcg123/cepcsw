# Primary-electron bremsstrahlung photon steps before ECAL

The user requested that the simulation truth recorder keep eBrem photons
generated by primary electrons/positrons inside the tracker and **all of each
photon's own Geant4 steps before first ECAL entry**. The user explicitly chose
first ECAL volume, not the tracker-region radius/z boundary, as the transport
stop condition. The maintained simulation card was not edited.

`GsfG4BremsPhotons` now requires a primary e-/e+ parent and a photon creation
position inside the configured tracker region. It records the assigned photon
track ID after Geant4 begins tracking (`-1` if never tracked). The secondary
pointer is used only transiently to associate birth with the assigned track ID;
it is not written to PODIO. `GsfG4BremsPhotonSteps` stores every step of each
matched photon up to and including the step whose post-point first belongs to
an ECAL touchable volume. `postInEcal` flags that entry step. If a photon stops
before ECAL, its last step is retained; if it does not reach ECAL, all tracked
steps are retained. No daughter-particle paths or ECAL-internal photon steps
are included. Per-step fields and relation are defined in
`Simulation/GsfTruthEventData/gsftruth.yaml` and described in its README.

The ECAL test searches all Geant4 touchable ancestors for ECAL volume names.
This is mechanically checked on the maintained `TDR_o1_v01` geometry, not
claimed as a universal naming contract for every CEPCSW geometry.

Build: `GsfTruthEventData`, `GsfTruthEventDataDict`, and `DetSimAna` passed in
the EL9/LCG105 configured build. No install was performed.

Same-seed barrel smoke: 20 primary e- events at 2 GeV and 85 degrees gave 44
tracker-born photons, 11,532 photon steps, and 28 first-ECAL-entry steps.
All photons had assigned track IDs and at least one step; all step-to-photon
relations were valid; no step followed a marked ECAL entry. The 28 ECAL-entry
post-points had radii 1830.02--1838.34 mm. The compressed ROOT file was
6,081,796 bytes versus 5,434,814 bytes for birth-only truth: +646,982 bytes
(11.9%) in this specific sample. The ROOT branch check confirmed unchanged
non-photon tracking/hit values; two material-step volume-copy-number branches
differed in 119 and 99 entries, respectively, while their positions and
process subtypes agreed. These copy numbers are geometry bookkeeping and the
cause of their drift was not further audited here.

Endcap smoke: 5 primary e- events at 2 GeV and 20 degrees gave 14 photons,
1,214 photon steps, and 13 first-ECAL-entry steps. All step-to-photon
relations and track IDs were valid. ECAL-entry post-points were at z=2930 mm.

A first PODIO check crashed because the test let its `Reader` object die before
using retained Frame objects. Keeping the reader alive resolved that test
error; direct PODIO iteration read all 44 photons and 11,532 linked steps.
The implementation remains uninstalled and is not a physics validation or
general multi-geometry guarantee. Smoke tuples are in `/tmp/` and are not
tracked project outputs.
