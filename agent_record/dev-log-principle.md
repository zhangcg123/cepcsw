# 开发日志记录原则

**`agent_record/DEVELOPMENT.md` 是开发日志的唯一总纲**，任何时候不应新建独立日志文件。

## 核心原则：累积追加，不覆盖删除

1. **关键发现**：按时间顺序编号，每次追加新条目到列表末尾，**不删除旧条目**
2. **根因分析演进**：从初疑 → 再疑 → 终疑，展示完整诊断链路，**旧的推测也保留**
3. **测试结果**：新的测试结果追加，旧的保留作为历史对比
4. **已完成**：追加新条目到列表末尾
5. **当前状态**：覆盖式更新（这是唯一允许覆盖的，因为只反映当前）
6. **下一步 / 待解决问题**：追加新条目，移除已解决的，保留未解决的

**Why:** 开发过程中思路会演进，早期的错误推测是理解当前结论的重要上下文。覆盖式记录丢失了排查路径，以后回头看会不理解"为什么得出这个结论"。
**How to apply:** 每次开发节点只更新 `DEVELOPMENT.md`，追加新内容，不覆盖旧内容（除"当前状态"外）。
